Resumo

O projeto é muito maior do que o snapshot de março sugeria: dois frontends, oito blueprints, oito agentes, mais de trinta scripts, OCR, três LLMs e sessenta documentos. A esteira de produtos funciona de ponta a ponta para o Mercado Livre. O Instagram está escrito sobre uma biblioteca não oficial que já foi bloqueada, com agentes mock. A recomendação de conteúdo é um scaffold numa branch separada, sem ligação com os produtos.

funciona Hoje

  • Mercado Livre completo: OAuth com refresh, API oficial + OCR para preço promo, link de afiliado matt_tool, menor vendedor no catálogo.
  • make prepare-ml → organize-tags → stage: produto no site com imagens no MinIO.
  • React SPA atrás de Nginx 443 com busca, paginação, tag e subtag; Jinja em paralelo para /catalogo e /secaoN.
  • make populate-mf: agente que enche o site com mais vendidos do ML por tag/subtag.
  • Túnel Cloudflare temporário com reconfiguração automática do callback OAuth.
  • Price oracle e tag classifier com LLM local (Ollama) quando a stack hsmart está de pé.

quebrado ou mock Escrito, não confiável

  • Instagram: instagrapi (usuário/senha, viola os termos, login já falha); decisor e enriquecedor são mocks; o decisor lê staging/*.json sem recursão e acha zero produtos.
  • Webhook e sync do ML quebram: marketplace_service usa uma instância de banco nunca inicializada.
  • tag_classifier --db é um no-op que gasta LLM; não conhece a tag ES.
  • Shopee e Amazon por scraping + OCR, sem API oficial, sem tag de afiliado na Amazon.
  • 62 dos 74 JSONs de staging têm R$ 0.00; o stage pula em silêncio.
  • CI sem testes; make up exige Qdrant + Ollama + hsmart; URL fixa do Cloudflare inoperante.

não existe Zero código útil

  • Graph API do Instagram (só documentação).
  • Observador de perfil seguido, hashtags ou menções.
  • Recomendação ligada a produtos reais (o scaffold lê o perfil do próprio usuário e nunca preenche embeddings).
  • Menor preço entre plataformas (só ML × vendedores do ML).
  • Fila de posts com aprovação humana; trilha de decisão dos agentes.
  • Autenticação nas rotas de escrita; domínio público estável; cron.

Esteira manual (comandos reais de hoje)

O que uma pessoa faz para subir um produto. O runbook completo com regras de preenchimento está na seção 3 do CLAUDE.md.

  1. Subir backend e túnelSobe db, minio, redis e site sem a stack de LLM, abre o túnel e imprime o link de autorização do Mercado Livre. Depois confira o token.
    make serve-cloudflare
make check-tokens
  2. Preparar o produtoInterativo: pede categoria (1 a 6) e subcategoria. Gera staging/<tag>/<sub>/<slug>_<ts>.json e baixa as imagens em uploads/<slug>/.
    make prepare-ml     URL="https://meli.la/xxxx"
make prepare-shopee URL="https://s.shopee.com.br/xxxx"
make prepare-amazon URL="https://amzn.to/xxxx"
  3. ConferirO preço precisa ter um dígito de 1 a 9, senão o stage pula o arquivo sem avisar. Opcionalmente confira o menor vendedor e reclassifique.
    make verify-product-cheaper URL="https://meli.la/xxxx"
make organize-tags
  4. Publicar no siteUpload para o MinIO, POST /add_product, registro em .processed, dedup do staging.
    make stage
  5. Verhttps://localhost pelo Nginx (React) ou https://localhost:5555 direto no Flask (Jinja). make links mostra as URLs públicas do túnel.
  6. Corrigir ou remover/admin (sem senha) ou DELETE /api/delete/<id>. Para atualizar preço: make api-update URL=... ou make update-ml-prices DRY=1 antes de rodar sem DRY.

Perigosos: make down-purge apaga banco, MinIO e Redis; make reprice-all apaga produtos com preço zero; make prd-down usa -v. Não use make instagram-post em produção.
